# 研发工作流程

## 资料进入项目

先清点文件数量、名称、格式和可读取范围，再写入 `data/source-index.json`。原始资料不直接复制到网站，研究时保留来源 ID。

## 知识蒸馏

每条知识至少拆成四层：

1. `original_observation`：资料实际说了什么；
2. `ai_analysis`：对资料的比较、推断和批评；
3. `distilled_rule`：项目决定保留的结论；
4. `validation_cases`：用真题或测试题验证迁移能力。

## 产品更新

知识条目通过审核后，才进入教材章节。教材页面要能说明适用场景、使用方法和禁用边界，不能只有一段英文模板。

## 双作者循环

```text
资料清点 → 条目提取 → 冲突比较 → 蒸馏建议 → 真题测试 → PR 审核 → 教材更新
```

每轮结束必须报告：读取资料、新增知识、与旧成果的区别、保留或修改的决策、可直接使用的内容和未解决问题。
